# 塌房型爱豆测评 · INCIDENT FILE

20 道原创情境题，8 种塌房方式。纯静态网页，无安装依赖、无账号、无服务器端接口。适合手机浏览器，可生成完整 PNG 结果长图。

**和「爱豆出道人设」是同一套引擎、同一套 DEBUT LAB 视觉体系，但是独立商品、独立链接、独立数据。** 两套不要混着部署，也不要共用域名路径。

---

## 部署到 GitHub Pages

仓库根目录必须能直接看到 `index.html`，**不要再套一层文件夹**。

1. 仓库 → `Add file` → `Upload files`
2. 把本目录里的**全部内容**拖进去（`index.html`、`README.md`、`.nojekyll`、`assets/`、`data/`、`scripts/`、`styles/`、`verify.mjs`）
3. 底部 `Commit changes`
4. 仓库 → `Settings` → `Pages` → `Source` 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`，`Save`
5. 等 1~2 分钟，访问 `https://<用户名>.github.io/tafangxing/`

> `.nojekyll` 这个空文件必须传上去。它告诉 GitHub Pages 不要跑 Jekyll 构建，直接按静态文件原样输出。
> 缺了它，带下划线或特殊字符的路径会被吞掉。

访问 404 的排查顺序：① Pages 分支/目录选错 ② 等构建没完成（`Actions` 页看进度）③ 仓库根目录多套了一层文件夹 ④ 仓库是 Private 且账号不支持私有仓库 Pages。

## 修改题目与结果

编辑 `data/questions.json` 与 `data/results.json`。使用支持 UTF-8 的文本编辑器，保持合法 JSON（英文双引号、无注释、末尾无多余逗号）。改完直接上传，不需要构建。

### 题目结构

```json
{
  "id": "q01",
  "chapter": "01 / BEFORE DEBUT",
  "title": "出道名单公布的前一晚，你在干什么？",
  "options": [
    { "id": "a", "text": "选项文案", "scores": { "instant": 3, "attitude": 1 } }
  ]
}
```

每道题必须保留 4 个不同 ID 的选项。`scores` 里主类型给 3 分、副类型给 1 分；**主类型是决定结果的那一分，副类型只用来打破平局**。

### 结果结构

8 个结果 ID：

| ID | 名称 | 塌房时间 | 引爆人 |
|---|---|---|---|
| `instant` | 秒塌 | 出道第 1 天 | 自己的小号 |
| `romance` | 恋爱脑 | 第 89 天 | 站姐 |
| `mouth` | 嘴臭 | 第 200 天 | 自己的旧微博 |
| `study` | 学术塌 | 第 400 天 | 高中同学 |
| `fandom` | 粉丝反噬 | 第 500 天 | 你自己的粉丝 |
| `attitude` | 耍大牌 | 第 700 天 | 前工作人员 |
| `faded` | 摆烂糊 | 从来没有 | 无人 |
| `phoenix` | 黑红不塌 | 塌了 8 次 | 全网 |

每个结果包含：

- `name` 类型名、`english` 英文副题、`kicker` 小标题、`tagline` 一句话设定
- `timeline` 塌房时间、`trigger` 引爆人、`level` 事故等级（S / A / B / —）**← 这三个是本商品新增字段**
- `position` 事故定性（只写结论，例如「态度翻车」，不要带「事故定性 /」前缀，页面会自己加）
- `color` 六位十六进制主题色
- `tags` 3 个标签
- `stats` 六项整数星级（1–5）：塌房速度 / 黑料浓度 / 公关水平 / 粉丝黏性 / 复出难度 / 话题余温
- `core` 事故经过、`quote` 粉丝后来说、`scene` 塌房现场
- `fans` 四类粉丝去留比例（整数合计 100）：连夜脱粉 / 观望中 / 塌了还爱 / 路人吃瓜
- `advice` 事后忠告

### 计分规则

纯加分制，总分最高者获胜；同分按 `tieBreakOrder` 从前到后决胜，不使用随机数。

**当前平衡度**：8 个类型各有 10 个主题入口（10×3=30 分）+ 10 个副题入口（10×1=10 分）= **最大可得 40 分，8 个类型完全相等**。

改题目时必须守住这条：**每道题的 4 个主类型不能重复，副类型必须取自该题的补集**。否则某个类型会天然占优，测出来会集中在少数几个结果上。

改完跑一次校验（需要本机装 Node）：

```text
node verify.mjs
```

会输出入口数、最大可得、平衡度、可达性、20000 次随机作答分布。要求：平衡差异 0%、8 个类型全部可达、随机分布都在 10%~15% 之间。

## 页面与图片

- `index.html`：入口、标题和描述（SEO / 分享卡片）
- `styles/main.css`：颜色、字号和手机适配
- `scripts/app.js`：页面状态、交互、结果渲染
- `scripts/core.js`：数据校验和计分（**不要动**，和爱豆人设版共用同一份）
- `scripts/poster.js`：原生 Canvas 结果长图排版
- `assets/incident-file.svg`：原创事故档案袋插画，无真人照片、无外部字体、无远程素材

结果页点击「保存结果图」生成 PNG，可下载或长按保存。结果图包含全部模块与娱乐说明。

答题进度只存在当前标签页的 sessionStorage，关闭标签页可能清除。不采集、不上传用户答案。

## 合规红线（改文案时别踩）

- **不指向任何真实艺人、真实事件**。评论区常见的「文泰一」「张峻豪」这类真实塌房案例，一个字都不能出现在题目和结果里。
- 不写「劣迹艺人」「资本」「皇族」这类容易被判定影射的词。
- 所有剧情必须是虚构情境，页脚已固定声明「不指向任何真实人物或事件」，不要删。
- 不写预测、诊断、保证类表述。

## 开发验证

```text
node verify.mjs                     # 数据校验 + 平衡度 + 可达性 + 随机分布
node shot.mjs <cdpPort> <baseUrl> ./shots        # 首页 / 答题页 / 结果页截图
node shot_all.mjs <cdpPort> <baseUrl> ./shots    # 8 种结果全量截图 + 8 张结果长图
```

截图脚本走比特浏览器 CDP（`xhs-note-collect` 技能里的 `cdp.mjs`），不需要装 Playwright。
